## B1 · `complete` падает на любом ZIP — блокер

**Где:** `apps/api/src/modules/uploads/uploads.service.ts:10`, `apps/api/tsconfig.json`

```ts
import AdmZip from 'adm-zip';        // строка 10
zip = new AdmZip(upload.storageKey); // строка 152
```

В `tsconfig.json` включён `allowSyntheticDefaultImports`, но нет `esModuleInterop`.
TypeScript пропускает импорт по умолчанию, а компилирует его без хелпера:

```js
// dist/src/modules/uploads/uploads.service.js
const adm_zip_1 = require("adm-zip");
zip = new adm_zip_1.default(upload.storageKey);   // default у CommonJS-модуля нет
```

**Что происходит:** `POST /v1/uploads/:uploadId/complete` → `400`
`Failed to read ZIP archive: adm_zip_1.default is not a constructor`, архив
переходит в `failed`. Дальше не пройти: нет сборки → нет публикации → нет каталога
и скачивания.

**ZIP при этом корректный:** тот же `adm-zip` через обычный `require` читает
сохранённый файл из `storage_data/uploads/` — все записи, размеры и CRC сходятся.

**Как исправить** (одно из двух):

```jsonc
// apps/api/tsconfig.json → compilerOptions
"esModuleInterop": true
```

```ts
// или в uploads.service.ts
import * as AdmZip from 'adm-zip';
```

Судя по всему, e2e-тесты этого не ловят (компиляция под jest, видимо, идёт иначе),
поэтому стоит проверить на собранном сервере: `npm run start:dev` → загрузка ZIP.

## B2 · Карточка по slug не отдаёт `cover_url`

**Где:** `apps/api/src/modules/marketplace/marketplace.service.ts`,
`getArchiveBySlug` — объект ответа (строки 193–229).

В каталоге (`listArchives`) поле есть, в карточке его нет, хотя `docs/API.md` §5
перечисляет обложку в ответе. Без обходного пути фронт отклонял бы ответ как
нарушение контракта — сейчас он временно читает отсутствие как `null`.

**Как исправить:** добавить в ответ `cover_url: listing.coverStorageKey || null`,
как в `listArchives`.

## B3 · `POST /uploads/:id/data` не проверяет владельца — безопасность

**Где:** `apps/api/src/modules/uploads/uploads.controller.ts:36–56` (`data`)
и `:58–85` (`file`), `uploads.service.ts` → `setUploadedFile` (строки 107–124).

Эндпоинт защищён `WalletAuthGuard`, но не берёт `@CurrentUser()` и не сверяет, чья
это загрузка. Любой вошедший автор, зная `upload_id`, может подменить файл чужой
загрузки до её `complete`. Остальные шаги (`init`, `complete`, `cancel`) владельца
проверяют.

**Как исправить:** передать `user.id` в `setUploadedFile` и отказывать, если
`upload.archive.creatorUserId !== userId` — так же, как в `complete`.

## B4 · Сортировки по популярности работают только внутри страницы

**Где:** `marketplace.service.ts`, `listArchives`, строки 112–122.

`skip`/`take` применяются в запросе к базе (порядок — `createdAt desc`), а
`popular_week`, `popular_month` и `most_downloaded` сортируют уже полученную
страницу в памяти. Самый популярный архив со второй страницы на первую не попадёт.
Заодно в каждый запрос каталога подгружаются все события и платежи всех архивов
страницы (`include: { events: true, payments: true }`).

**Как исправить:** считать метрики агрегатом в базе (с фильтром окна) и сортировать
до пагинации. Для MVP хватит и простого варианта: выбрать все опубликованные,
отсортировать, потом резать на страницы.

## B5 · Сбой создания ATA проглатывается

**Где:** `archives.service.ts`, `publish` (строки 281–305) и `formatCreatorArchive`
(строка 68).

Если USDC ATA автора не удалось проверить или создать, ошибка уходит в
`logger.warn`, и архив всё равно публикуется. А `payout_account_ready` считается как
`Boolean(arc.creatorUsdcAta)` — адрес вычисляется при создании архива, поэтому поле
всегда `true`. Фронт гасит кнопку публикации по этому полю, и сейчас гасить её не на
чем. Автор может опубликовать архив, выплаты по которому не дойдут.

**Как исправить:** отдавать в `payout_account_ready` реальное состояние аккаунта
в сети, а при неудаче в `publish` отвечать `409 PAYOUT_ACCOUNT_NOT_READY`, а не
публиковать молча. Мягкий режим для dev/test можно оставить за флагом окружения.

## B6 · `cancel` оставляет архив в `uploading`

**Где:** `uploads.service.ts`, `init` (строки 95–98) и `cancel` (строки 307–327).

`init` сразу переводит архив в `uploading`, а `cancel` меняет только статус самой
загрузки. Отменённая или оборванная загрузка оставляет архив в `uploading` навсегда:
кабинет фронта опрашивает переходные статусы и не прекращает опрос.

**Как исправить:** в `cancel` возвращать архиву прежний статус (`draft`, если файлов
нет, иначе `ready`).

## B7 · Сборщик `.slr` — заглушка

**Где:** `apps/api/src/modules/uploads/archive-builder.adapter.ts`, `build`.

В контейнер пишутся заголовок и случайные байты (`ENC_MANIFEST_MOCK:` +
`randomBytes`). Файлы автора, которые `complete` распаковал и проверил, в `.slr`
не попадают. Скачанный `.slr` Viewer открыть не сможет.

Вопрос, а не претензия: это осознанная заглушка до интеграции с `solarch-cli`
из ветки viewer? Если да — стоит отметить это в `frontback.md`, там сейчас
«100% готов».

## B8 · Чужой архив — 403 вместо 404

**Где:** `archives.service.ts` — `findOne` (строки 189–191) и остальные
`ForbiddenException('You do not own this archive')`.

403 подтверждает, что архив с таким id существует. Фронт показывает 403 и 404
одинаково («архива нет»), так что это не ломает интерфейс. Но 404 скрывал бы сам
факт существования чужого архива.

**Предложение:** отвечать 404 на чужой архив так же, как на несуществующий.

## B9 · `PATCH` ждёт `cover_storage_key`, контракт — `cover_url`

**Где:** `archives.dto.ts`, `UpdateArchiveDto` (строки 76–78).

В `docs/API.md` и на фронте поле называется `cover_url`. `ValidationPipe`
с `forbidNonWhitelisted: true` ответит 400 на запрос, где будет `cover_url`.
Сейчас фронт обложку не отправляет, поэтому это не ломается — но упрётся в первую же
загрузку обложки. Связано с открытым вопросом Q3: как вообще загружается обложка.

**Предложение:** договориться об имени и способе загрузки обложки (Q3) и привести
DTO и `docs/API.md` к одному виду.

## B10 · Выход не отзывает JWT

**Где:** `auth.controller.ts`, `logout` (строки 41–46); `JWT_EXPIRES_IN="7d"`.

`logout` отвечает `{ success: true }` и ничего не делает: токен остаётся
действительным 7 дней. Фронт стирает токен у себя, так что для интерфейса выход
работает. Но украденный токен выходом не обезвредить.

**Предложение (не срочно для MVP):** короткий срок жизни токена или список отозванных
`jti` на время жизни токена.

## B11 · `frontback.md` расходится с кодом

Фронт сверялся с кодом, а не с документом. Код ближе к общему контракту, чем
его описание:

| В `frontback.md` | В коде |
|---|---|
| элемент каталога с `id` | `archive_id` |
| `price.amount: 25.00` — число | строка (`priceAmount` — `String` в Prisma) |
| `economics`: `price_usdc`, `creator_payout_usdc`, `platform_fee_usdc`, `solana_network_fee_paid_by` | `platform_fee_bps`, `creator_share`, `platform_share`, `network_fees_paid_by` |
| параметры каталога `sort_by` (`newest`, `popular`…), `query` | `sort` (`popular_week`, `popular_month`, `most_downloaded`, `price_asc`, `price_desc`), `search` |
| `init`: `file_name`, `file_size` | `filename`, `size_bytes` |
| «схема `marketplaceArchiveDetailSchema` валидирует ответ на 100%» | без `cover_url` не валидирует (B2) |

**Предложение:** поправить примеры в `frontback.md` (и в
`docs/FRONTEND_BACKEND_INTEGRATION_GUIDE.md` на ветке backend) под фактический
формат ответов.
